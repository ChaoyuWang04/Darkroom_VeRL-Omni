# S1 · 判据体系（2 周）★ 项目核心

## 背景

判据 = verifier = reward，三者在本项目里是同一个东西。**判据错一次 = 训练信号错一批**。所以顺序必须是「先把尺子做出来并量准，再造数据」——这是 Syncopate「定目标 → 定尺子 → 造数据」的直接搬运。

现状：**四层全空**。这一章从零建判据，并且——比建判据更重要的是——**测判据自己准不准**（T1.7）。

## 任务

| ID | 任务 | 背景与动作 | 产出 |
|---|---|---|---|
| **T1.1** | 规格库 v0 | 平台规则要能被精确查询、可版本化。定义 schema（canvas/safe_zone/required_elements/brand/banned_terms/valid_to/version）+ 填入真实数据 | `src/spec/registry.py`<br>`data/specs/*.yaml` |
| **T1.2** | L1 合规 gate | 违禁词表 + 匹配（含变体/谐音）。**这是 gate 不是分数** | `src/verifier/l1_compliance.py` |
| **T1.3** | L2 文案渲染（扩展） | 已有目标文案 OCR；**新增全图 OCR → gibberish 检测**：识别出的文本集合减去请求文本集合，剩下的就是乱码 | `src/verifier/l2_text.py` |
| **T1.4** | L3 结构判据 | 元素检测（开放词表检测器：logo / CTA / product）+ 几何计算（安全区、尺寸、文字面积占比） | `src/verifier/l3_layout.py` |
| **T1.5** | L4 品牌/美学 | 主色 CIEDE2000 ΔE + HPSv2 打分 | `src/verifier/l4_brand.py` |
| **T1.6** | ★★★ **判据自测集** | **人工标注 200 张图的逐层 ground truth**——这是全项目最不可省的人工投入 | `data/verifier_eval/annotations.jsonl` |
| **T1.7** | ★★★ **判据准确率测量** | 用 T1.6 的标注，测每层判据自己的 precision/recall | `tests/test_verifier_accuracy.py`<br>`docs/reports/verifier-accuracy.md` |
| **T1.8** | reward 组装 | 加权和 + 5 个 cap + gate 短路 | `src/verifier/reward.py` |
| **T1.9** | 吞吐 benchmark | 判据不能成为训练瓶颈 | `tests/bench_verifier.py` |

# S2 · base 侦察（4 天）★ 决定 SFT 打哪

## 背景

设计文档 §14.1：**SFT 该吃最难的，不是最好看的**——但"最难"是相对 base 而言的。base 已经会的（英文短词渲染）SFT 不该碰，base 完全不会的（密集中文版式）才是 SFT 的目标。

这个判断**只能靠实测**，不能靠猜。这一章的产出是一张热力图，它决定 S3 造什么数据、S4 训什么。

## 任务

| ID | 任务 | 背景与动作 | 产出 |
|---|---|---|---|
| **T2.1** | Prompt 生成器 | 程序化造需求：文案模板 × 平台 × 尺寸 × 品类 × 语言。**RL 阶段只要 prompt 不要图**，这个生成器是 RL 数据的全部来源 | `src/data/prompt_gen.py` |
| **T2.2** | 有效格子枚举 | 任务(T01–T10) × 难度(L1–L5)，剔除无效组合，得到格子清单 | `data/grid.yaml` |
| **T2.3** | EVAL 集切分并**冻结** | 每格 ≥ 20 条，写死 request_id 清单，单独文件，永不训练 | `data/splits/eval.jsonl` |
| **T2.4** | ★★★ **多底座基线审计** | **2–3 个候选底座**各跑一遍：每格采 G=16 张、跑全套判据、统计 mean/std。⚠️ **必须 bf16**，量化会低估文字渲染——正好是我们的主锚 | `scripts/base_audit.py`<br>`docs/reports/base-baseline.md` |
| **T2.5** | ★ **底座裁决 + SFT 目标决策** | 选底座的标准是**有梯度格占比最高**，不是「最强」；再读出饱和格（不碰）/ 全灭格（SFT 攻） | 写入 `base-baseline.md` §决策 |

### T2.4 的三分类定义（可脚本化）

对每个格子，采 $G=16$ 条，得到 reward 序列 $\{r_i\}$：

| 分类 | 判据 | 含义 |
|---|---|---|
| **饱和** | $\bar r > 0.90$ 且 $\sigma < 0.05$ | base 已经会 → **SFT 不该碰** |
| **全灭** | $\bar r < 0.10$ | base 完全不会 → **SFT 的攻击目标** |
| **有梯度** | $\sigma \ge 0.05$ 且 $0.10 \le \bar r \le 0.90$ | → **留给 RL** |

## ★ 章节验收

| # | 指标 | 定义 | 通过线 | 检查方式 |
|---|---|---|---|---|
| A2.1 | 格子覆盖 | 被审计的有效格子 / 全部有效格子 | **= 1.00** | `base_audit.py --check-coverage` |
| A2.2 | 采样充分性 | 每格样本数 | **≥ 16** | 同上 |
| A2.3 | EVAL 冻结 | eval.jsonl 的 SHA-256 已记录并锁定 | 文件存在且 hash 入库 | `test_split_leakage.py` |
| **A2.4** | **EVAL 零泄漏** | EVAL ∩ (SFT池 ∪ RL池)，按 prompt SHA-256 | **= 0** ★ 硬性 | 同上 |
| A2.5 | 基线报告完整性 | 报告含：三分类占比 + 分任务 + 分难度 + 分语言 四张分桶表 | 4/4 表齐全 | 人工 + `--check-report` |
| **A2.6** | **决策可执行** | 明确列出「SFT 攻击格子清单」 | 清单非空，且 ⊆ 全灭格 | 人工确认 |
| A2.7 | 通用能力基线 | 选定底座在隔离评估集（通用 T2I）上的 GenEval / HPS | 数值已记录 | `scripts/eval_general.py` |
| **A2.8** | **底座候选数** | 参与对照的底座数量 | **≥ 2** | `base_audit.py --list-backbones` |
| **A2.9** | **精度约束** | 审计推理精度 | **= bf16**（非量化） | 脚本内断言 |
| **A2.10** | **单卡可训性实测** | 选定底座能否在 32GB 单卡跑 LoRA 训练一步 | **实测结论已记录**（能/不能，不预设） | `scripts/probe_trainable.py` |

⚠️ **A2.7 是 D1 防遗忘的参照系**。没有它，后面无法判断"训完只会画广告图"。

## 回退

| 现象 | 含义 | 动作 |
|---|---|---|
| 全灭格 > 60% | 任务定义超出 base 能力太多 | 降难度定义 / 缩小第一版任务范围（先只做 T01–T04） |
| 饱和格 > 50% | 任务太简单，训了也没提升空间 | 提高难度轴（加长文案、加中英混排比例） |
| 有梯度格 < 20% | **RL 会没东西可训** | 调判据阈值让 reward 更连续；或调 prompt 难度分布 |

# S4 · SFT（1 周，5090 单卡）

## 背景

图像 SFT 是**挪分布**不是**教答案**（同一个 flow matching loss，只换数据）。它的 KPI **不是判据分高**，而是「RL 能不能训得动」——把全灭格子的 $p$ 从 0 抬到 5–10%，让 GRPO 有梯度可用。

⚠️ **设计文档 v0.1 修正**：`degrade` / `reject` 两个 behavior **不由扩散模型产生**（它的输出空间里只有图）。第一版由**前置规则层**实现——文案字符数 vs 可用面积可算，违禁词可查表。SFT 不训 behavior 分类。

## 任务

| ID | 任务 | 背景与动作 | 产出 |
|---|---|---|---|
| **T4.1** | 前置决策层 | 纯规则实现 generate/clarify/degrade/reject 四分类 + degrade 替代方案生成 | `src/gate/decision.py` |
| **T4.2** | 文案 sanitizer | 防注入：copy 字段只作为待渲染文本，指令性内容剥离并告警 | `src/gate/sanitize.py` |
| **T4.3** | SFT 训练脚本 | diffusers / DiffSynth-Studio，LoRA rank 64 | `scripts/train_sft.sh` |
| **T4.4** | SFT 训练 + 毕业检查 | 训完跑毕业条件全套 | `docs/reports/sft-graduation.md` |
| **T4.5** | 训推一致性检查 | SFT 侧与 rollout 侧的 prompt 构造、分辨率、scheduler 配置逐项 diff | `tests/test_train_infer_parity.py` |

## ★ 章节验收（SFT 毕业条件）

| # | 指标 | 定义 | 通过线 | 检查方式 |
|---|---|---|---|---|
| **A4.1** | **零梯度格占比** | 三分类里"饱和 + 全灭"的格子占比 | **< 30%** ★ 最硬的一条 | `base_audit.py --ckpt sft` |
| **A4.2** | **目标格解锁** | S2 标出的"SFT 攻击格"，每格 $\bar r$ | **≥ 0.05**（从 ≈0 抬起） | 同上 |
| **A4.3** | **采样多样性** | 同 prompt 采 8 张，版式聚类数 ≥ 2 的比例 | **≥ 0.70** ★ 防模板塌缩 | `scripts/diversity_check.py` |
| **A4.4** | **D1 通用能力** | 隔离评估集 GenEval，相对 A2.7 基线的下降 | **≤ 3%** ★ 防灾难性遗忘 | `scripts/eval_general.py` |
| A4.5 | 判据可跑完率 | 生成图能被判据链完整判定（不崩） | **≥ 0.99** | `test_verifier_robustness.py` |
| A4.6 | deliverable 提升 | EVAL 上一次通过率，相对 base | **≥ base + 10 个百分点**【基线后填具体值】 | `scripts/eval_deliverable.py` |
| **A4.7** | **前置层四分类准确率** | 规则层 vs 人工标注（用 T3.6 负样本集） | **≥ 0.95**（规则实现，应该很高） | `test_decision_gate.py` |
| **A4.8** | **注入抵抗** | N5 注入样本上产出违规内容的比例 | **= 0** ★ 硬性 | `test_injection.py` |
